# Project Guide — Customer Churn Prediction Service (v2)

A production-shaped churn system: a **calibrated** model, a **versioned registry**,
a **REST API** for real-time scoring, **batch scoring**, **input validation +
drift monitoring**, **structured logs + Prometheus metrics**, containers and CI.

> `README.md` is the short tour. `models/registry/<version>/model_card.md` has the
> live numbers for the current model.

---

## 0. The one setup rule

**Activate the virtual environment in every terminal**, then run commands from the
project root:

```powershell
.\.venv\Scripts\Activate.ps1        # Windows PowerShell — prompt shows (.venv)
```
```bash
source .venv/bin/activate           # Linux / macOS
```

Not activating is the #1 source of `ModuleNotFoundError`. Without activation,
prefix commands with `.\.venv\Scripts\python.exe` and use `python -m …` forms
(`python -m pytest`, `python -m streamlit run app.py`).

If `.venv/` is missing or broken (e.g. Python version changed):
```powershell
Remove-Item -Recurse -Force .\.venv
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt
```

## 1. What it does

Given a customer's 19 attributes → **calibrated churn probability**, a **risk
tier** with a recommended action, the **top drivers** of that specific
prediction, and **warnings** if any input is outside what the model was trained
on. Same result whether you call the Python API, the CLI, the REST API or the
dashboard — they all load one registered model.

| Use | Command |
| :-- | :-- |
| Train / calibrate / register a model | `python -m churn train` |
| Real-time HTTP scoring | `python -m churn serve` → `POST http://localhost:8000/predict` |
| Score one customer in a terminal | `python -m churn predict --tenure 4 …` |
| Score a CSV | `python -m churn score --input in.csv --output out.csv` |
| Drift report for a new batch | `python -m churn drift --current new.csv` |
| Manage model versions | `python -m churn registry {list,show,promote}` |
| Interactive dashboard | `streamlit run app.py` |

Dataset: public **Telco Customer Churn** — 7,043 customers, 21 columns, ~26.5% churn.

## 3. Configuration (`churn/config.py`)

`.env` file — see `.env.example`).

| Setting | Env var | Default | Meaning |
| :-- | :-- | :-- | :-- |
| `data_path` | `CHURN_DATA_PATH` | `data/Telco-Customer-Churn.csv` | training CSV |
| `models_dir` | `CHURN_MODELS_DIR` | `models` | registry lives in `<models_dir>/registry` |
| `model_version` | `CHURN_MODEL_VERSION` | `latest` | which registered version to serve |
| `calibration` | `CHURN_CALIBRATION` | `auto` | `auto` \| `sigmoid` \| `isotonic` \| `none` |
| `prediction_log_path` | `CHURN_PREDICTION_LOG_PATH` | *(none)* | JSONL audit log of every prediction |
| `api_url` | `CHURN_API_URL` | *(none)* | set → the dashboard calls this API instead of loading locally |
| `api_batch_limit` | `CHURN_API_BATCH_LIMIT` | `1000` | max customers per `/predict/batch` |
| `log_json` | `CHURN_LOG_JSON` | `false` | JSON logs (the API sets this in containers) |
| `random_state` / `test_size` / `cv_folds` / `selection_metric` | `CHURN_…` | 42 / 0.2 / 5 / roc_auc | modelling knobs |

## 4. The model (`churn/train.py`, `churn/model.py`, `churn/evaluate.py`)

### 4.1 Pipeline (`churn/features.py`)
Every candidate is one `Pipeline`: `FunctionTransformer(add_engineered)` →
`ColumnTransformer` → classifier.
* **Engineered** (row-local, robust to partial input): `tenure_group`,
  `has_internet`, `num_addons`.
* **Numeric** (`tenure, MonthlyCharges, TotalCharges, num_addons`): median impute → `StandardScaler`.
* **Categorical** (15 + `tenure_group`): most-frequent impute → `OneHotEncoder(handle_unknown="ignore")`.
* **Passthrough**: `SeniorCitizen`, `has_internet`.

### 4.2 Selection
Three candidates — `LogisticRegression`, `RandomForest`, `HistGradientBoosting`,
all `class_weight="balanced"` — each grid-searched once with a **multi-metric
stratified 5-fold** `GridSearchCV` (roc_auc / pr_auc / f1 / recall / precision).
Ranked by **ROC-AUC rounded to 3 dp**; ties (all three land ≈ 0.846) broken by
**recall** → Logistic Regression is selected. A `note:` line explains it when the
winner isn't the raw ROC-AUC leader.

### 4.3 Calibration  *(new in v2)*
`class_weight="balanced"` makes raw probabilities untrustworthy — a problem when
probabilities drive the risk bands. So the winner is wrapped in
`CalibratedClassifierCV(..., method=<auto>, cv=5, ensemble=False)`:
* `method` is chosen (`sigmoid` vs `isotonic`) by lower CV **Brier score**.
* `ensemble=False` keeps one base estimator → serving stays ~10 ms.
* Threshold tuning and the test report then run on the **calibrated** output.
The model card reports the **Brier score** (currently ≈ 0.138) and a reliability
curve.

The saved `ChurnModel` keeps **two** pipelines: `pipeline` (calibrated, for
probabilities) and `base_pipeline` (uncalibrated, for `top_factors` coefficients).

### 4.4 Decision threshold
Tuned on **out-of-fold** calibrated probabilities to maximise churn-class F1
(default) or recall-at-precision≥0.5 (`--threshold-objective recall_at_precision`).
Currently ≈ **0.35** on the calibrated scale.

### 4.5 Current numbers *(see the model card for live values)*
Selected `logistic_regression`; test **ROC-AUC ≈ 0.842**, **PR-AUC ≈ 0.64**,
**Brier ≈ 0.138**, recall ≈ **0.72** / precision ≈ **0.56** at the tuned threshold.

## 5. Model registry (`churn/registry.py`)

`python -m churn train` writes `models/registry/<version>/` (version =
`YYYYMMDDThhmmssZ`) and promotes it to `latest`. Each version has a
`manifest.json` with full provenance: git SHA, Python / sklearn / numpy versions,
**SHA-256 of the training CSV**, row counts, all CV & test metrics, calibration
method, and a training-distribution summary.

```bash
python -m churn registry list                 # every version, newest last, * = latest
python -m churn registry show 20260905T004924Z # print a manifest
python -m churn registry promote <version>     # roll back / forward
```
Serve a pinned version with `CHURN_MODEL_VERSION=<version>` (env) or
`--model-version` on `predict` / `score` / `drift`.

## 6. Input validation & drift (`churn/validation.py`)

At training time `TrainingStats.from_frame` snapshots every feature's range and
distribution onto the model.

* **Per-request validation** — every prediction (CLI + API + batch) returns a
  `warnings` list: numeric values outside the training range, categorical values
  never seen in training. The prediction is still produced.
* **Drift report** — `python -m churn drift --current new.csv` computes the
  **Population Stability Index** per feature vs. the training data; PSI > 0.2 is
  flagged as drift (exit code 1). Use it before trusting predictions on a new
  population.
* **Audit log** — set `CHURN_PREDICTION_LOG_PATH=logs/predictions.jsonl` and every
  prediction (features + output + warnings + model version) is appended as JSON.

## 7. REST API (`churn/service/`, `api.py`)

```bash
python -m churn serve                       # dev: 127.0.0.1:8000, add --reload
uvicorn api:app --host 0.0.0.0 --port 8000  # prod-style; scale with --workers N
```
Interactive docs at `http://localhost:8000/docs`.

| Method & path | Body | Response |
| :-- | :-- | :-- |
| `GET /health` | — | `{status, model_version, uptime_seconds}` — 503 if no model |
| `GET /model` | — | version, metrics, threshold, calibration, feature names |
| `POST /predict` | `CustomerFeatures` (all 19 optional) | `{churn, probability, risk_tier, threshold, top_factors, warnings, model_version, request_id, latency_ms}` |
| `POST /predict/batch` | `{customers: [CustomerFeatures, …]}` (≤ `api_batch_limit`) | `{model_version, count, predictions: [...]}` |
| `GET /metrics` | — | Prometheus exposition (`churn_predictions_total{tier}`, `churn_prediction_latency_seconds`, …) |

* Unknown field or bad enum → **422** with `{detail, request_id}`. Negative
  numerics → 422. Large-but-plausible values → scored, with a `warning`.
* Every response carries an `x-request-id` header; logs are JSON with that id
  when `CHURN_LOG_JSON=true`.
* Warm single-prediction latency ≈ **10–25 ms**.

```bash
curl localhost:8000/health
curl -X POST localhost:8000/predict -H 'content-type: application/json' \
     -d '{"tenure":4,"Contract":"Month-to-month","InternetService":"Fiber optic"}'
```

## 8. Containers & CI

```bash
docker compose run --rm api python -m churn train   # populate the shared models/ volume
docker compose up                                   # API :8000  +  dashboard :8501
```
`docker-compose.yml` runs the API and a dashboard configured with
`CHURN_API_URL=http://api:8000` (dashboard calls the API). The `Dockerfile` is
multi-stage on `python:3.12-slim` with a `HEALTHCHECK`.

`.github/workflows/ci.yml`: `ruff check` → `pytest` → `python -m churn train`
smoke → upload the model card artifact.

`Makefile` targets: `install train test lint format serve app score drift
registry docker-build docker-up clean`.

> Docker is **not run in this dev environment** (no daemon) — the compose file
> and Dockerfile are written and lint-checked, and the `uvicorn api:app`
> entrypoint is verified locally.

## 10. Troubleshooting

| Symptom | Fix |
| :-- | :-- |
| `ModuleNotFoundError: pandas/fastapi/...` on `python -m churn …` | venv not activated → `.\.venv\Scripts\Activate.ps1` (prompt shows `(.venv)`). Or use `.\.venv\Scripts\python.exe -m churn …`. |
| `pytest` / `streamlit` / `ruff` : *not recognized* | Same — activate, or use `python -m pytest` etc. |
| `Importing the numpy C-extensions failed … cp312 … python 'cpython-314'` | `.venv` upgraded across Python versions. Delete `.venv` fully and recreate (see §0). |
| `Model registry … is empty. Run python -m churn train` | No model yet — `python -m churn train`. |
| API `/predict` → 503 | The API started before a model was registered. Train, then restart (`python -m churn serve`). |
| Streamlit shows a stale prediction after retraining | `@st.cache_resource` — stop (Ctrl-C) and restart `streamlit run app.py`. |
| `python` opens the Microsoft Store | App-execution-alias stub. Activate the venv or use `.\.venv\Scripts\python.exe`. |
| Prediction probability looks extreme for a weird input | Check the `warnings` field — the input is outside the training envelope; run `python -m churn drift` on the batch. |

## 11. End-to-end flow

```
data/Telco-Customer-Churn.csv
   │ data.py: load_raw → coerce_features → clean → split (80/20 stratified)
   ▼
 x_train, y_train ─► for each candidate (model.py): GridSearchCV 5-fold, 5 metrics
   │                     pipeline = engineer → preprocess → classifier
   ▼
 select_best  (ROC-AUC to 3dp, tie-break on recall)  →  Logistic Regression
   │
   ├─► choose_calibration_method (Brier)  →  calibrate(ensemble=False)   [model.py]
   │
   ├─► optimal_threshold on out-of-fold *calibrated* probabilities        [evaluate.py]
   │
   ├─► test_report on the held-out 20%  (ROC-AUC, PR-AUC, Brier, reliability)
   │
   └─► TrainingStats.from_frame(x_train)                                  [validation.py]
   ▼
 ModelRegistry.save → models/registry/<version>/{model.joblib, manifest.json, model_card.md}
                    → latest.json                                          [registry.py]
   │
   ├─► python -m churn predict / score / drift                            [cli.py, batch.py]
   ├─► uvicorn api:app   →  /predict  /predict/batch  /metrics            [service/]
   └─► streamlit run app.py   (local model, or CHURN_API_URL → the API)  [app_ui.py]
```
